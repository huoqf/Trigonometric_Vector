# MathVision Architecture Rules

本文件定义 MathVision 项目的目录边界、模块职责、数据流方向与新增功能接入方式。所有 Agent 在新增、修改或重构代码时必须遵守。

## 1. 总体架构原则

### 1.1 单向数据流
项目必须维持严格的单向数据流：

**用户交互 → Store 中的唯一真值 → 纯函数派生 → UI 渲染**

禁止反向写入派生结果，禁止在多个层级同时维护相同语义的数据副本。

### 1.2 真值唯一性
所有数学页面的核心状态必须收敛到最少的基础变量中，例如：

- 角度
- 半径
- 控制开关
- 当前题目索引
- 当前练习状态

禁止将 `sin`、`cos`、`tan`、坐标点、投影值、图像采样点等派生量作为长期状态持久化。

### 1.3 职责分层
项目代码必须按职责分层，不得混用：

- `src/math/`：数学纯函数层
- `src/utils/`：通用工具层，尤其是坐标转换、格式化、边界工具
- `src/store/`：全局状态层，只保存真值和控制标记
- `src/features/`：具体交互实验与页面功能
- `src/components/`：通用 UI 组件
- `src/types/`：跨模块类型定义

任何模块都不得越层承担本不属于自己的职责。

## 2. 目录边界规则

### 2.1 `src/math/`
该目录只允许存在纯数学逻辑。

允许：
- 纯函数
- 向量运算
- 三角函数恒等变换
- 几何计算
- 公式识别与变换辅助函数

禁止：
- React Hooks
- DOM API
- `window` / `document`
- Zustand / Redux / 任何 store 访问
- CSS / 样式
- SVG / Canvas 绘制
- 副作用
- 随机数
- 时间依赖逻辑

### 2.2 `src/utils/`
该目录只允许放与业务无关或弱业务相关的工具函数。

允许：
- 坐标映射
- 数值规范化
- 格式化
- 轻量通用工具

禁止：
- 页面渲染
- 数学真值缓存
- 业务状态维护
- 直接操作 store

### 2.3 `src/store/`
该目录只允许保存唯一真值、控制状态、会话状态和显式用户操作结果。

允许：
- 当前角度
- 当前半径
- 当前题号
- 当前模式
- 错题持久化记录
- 显式用户收藏标记

禁止：
- 派生几何坐标
- 三角函数值缓存
- 绘图结果缓存
- 与渲染强绑定的中间结果
- 可以随基础状态即时计算出来的值

### 2.4 `src/features/`
该目录是页面与交互实验的实现层。

允许：
- 页面组件
- SVG / 交互逻辑
- 本地 UI 状态
- 用户输入响应
- 对 `src/math/` 和 `src/utils/` 的调用

禁止：
- 重复实现数学基础函数
- 复制坐标转换逻辑
- 直接改写 Store 的派生数据结构
- 引入跨 feature 的隐式耦合

## 3. 新模块接入规则

### 3.1 新功能优先复用现有架构
新增实验或页面时，优先复用以下现有能力：

- `ThreeScreenLayout`
- `coordinate.ts`
- `vector.ts`
- `trigonometry.ts`
- 现有 Zustand Store
- 现有题库和提示系统

禁止为了局部便利重建一套平行架构。

### 3.2 新功能必须先定义边界
新增模块前必须明确：

- 它属于数学层、UI 层还是题库层
- 它是否需要新的 Store
- 它能否复用已有布局
- 它是否只应新增纯函数
- 它是否需要测试

边界不清时，不得直接编码。

### 3.3 新功能默认不新增真值
除非现有真值无法表达业务，否则不得新增新的长期状态字段。

优先策略：
- 先考虑是否可由既有基础变量表达
- 再考虑是否可通过纯函数派生
- 最后才考虑是否需要新增 Store 字段

## 4. 复用与去重

### 4.1 复用优先
如果已有模块能满足 70% 以上需求，应优先扩展现有模块，而不是新建平行实现。

### 4.2 去重强制
以下内容必须避免重复造轮子：

- 坐标转换
- 向量运算
- 三角恒等变换基础函数
- 三屏布局
- 错题存储逻辑
- 题目状态管理

### 4.3 同类能力统一出口
同一类能力必须只有一个推荐入口，例如：

- 坐标转换统一走 `src/utils/coordinate.ts`
- 向量运算统一走 `src/math/vector.ts`
- 三角派生统一走 `src/math/trigonometry.ts`

不得在 feature 内私自复制同类逻辑。

## 5. 技术边界

### 5.1 路径别名
必须使用 `@/` 路径别名。

禁止：
- `../`
- `../../`
- 过深相对路径

### 5.2 纯函数优先
数学相关逻辑必须尽量实现为纯函数。

纯函数要求：
- 同输入同输出
- 无副作用
- 不依赖外部可变状态

### 5.3 明确奇异点处理
涉及 `tan` 等奇异点的逻辑，必须显式处理边界，不得让异常值污染 UI 或 Store。

## 6. 验收要求

新增模块完成后，必须确认：

- 目录边界未被破坏
- 派生量未进入 Store
- 现有功能未被回归破坏
- 复用路径清晰
- 结构与 ROADMAP_PROGRESS.md 一致
- 必要时补充测试
