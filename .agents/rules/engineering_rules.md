\# MathVision Engineering Rules



本文件定义 MathVision 项目的编码纪律、状态管理纪律、计算纪律、测试纪律与实现细则。所有 Agent 在写代码前必须遵守。



\## 1. 编码总原则



\### 1.1 先约束，再实现

任何新增代码必须先满足架构约束，再考虑功能细节。



实现顺序固定为：



1\. 明确输入与输出

2\. 确定真值来源

3\. 确定派生逻辑

4\. 确定 UI 呈现

5\. 补充测试

6\. 更新进度文档



禁止先写 UI 再补数学逻辑，禁止先写页面再倒推数据模型。



\### 1.2 增量优先

所有改动必须尽量保持增量式，不得在已有稳定模块上做破坏性重构，除非明确必要。



\### 1.3 可测试优先

每个新增数学函数、状态变换、边界处理都应尽可能可测试。



\## 2. 状态管理纪律



\### 2.1 Store 只保存真值

Zustand 或任何全局状态层只能保存：



\- 用户显式操作结果

\- 页面级真值

\- 会话状态

\- 持久化题库记录

\- 模式开关



禁止保存：



\- `sin/cos/tan`

\- 投影长度

\- 坐标点的派生结果

\- 几何中间态

\- SVG 计算点

\- 函数图像采样数组

\- 可以通过基础变量即时计算出的任何内容



\### 2.2 派生量只在渲染或局部计算中出现

派生量只能由以下方式出现：



\- `useMemo`

\- 纯函数即时计算

\- 渲染时局部生成



禁止把派生量再写回 Store。



\### 2.3 状态更新必须明确语义

状态更新函数必须语义明确，例如：



\- `setAngle`

\- `setRadius`

\- `submitAnswer`

\- `toggleHint`

\- `markWrongQuestion`



禁止使用语义模糊的通用更新器替代清晰动作。



\## 3. 数学计算纪律



\### 3.1 数学逻辑必须纯净

`src/math/` 中的所有函数必须满足：



\- 无副作用

\- 无 UI 依赖

\- 无 DOM 依赖

\- 无随机性

\- 无时间依赖



\### 3.2 奇异点与边界显式处理

对于三角函数中的边界点、奇异点、退化情形，必须显式处理。



要求：

\- `tan` 在不可定义点返回 `null`

\- 角度必须规范化到既定区间

\- 零向量、退化三角形、重合点必须单独处理

\- 不得把 `Infinity`、`NaN` 直接交给 UI 层



\### 3.3 统一数值策略

数值判断必须使用统一工具处理，例如：



\- 浮点误差比较

\- 接近零判断

\- 区间归一化

\- 夹角范围修正



禁止在各组件中散落重复的魔法阈值。



\## 4. UI 实现纪律



\### 4.1 三屏布局优先复用

适合教学表达的模块必须优先复用 `ThreeScreenLayout` 或既有类似布局。



新增布局前必须先判断是否真的无法复用。



\### 4.2 SVG 优先

对于几何、函数图像、向量、单位圆、三角形等可视化，优先使用 SVG。



除非有明确性能或交互需求，否则禁止用 Canvas 替代现有 SVG 体系。



\### 4.3 交互必须即时

拖拽、滑块、点选、切换模式必须保持实时响应。



禁止：

\- 人为延迟更新核心图形

\- 依赖低频轮询

\- 通过无意义缓存制造“假平滑”



\### 4.4 样式必须克制

UI 风格应保持简洁、明确、学习导向。



禁止：

\- 多余装饰

\- 视觉喧宾夺主

\- 与数学内容无关的花哨动效

\- 不一致的色彩语义



\## 5. 代码组织纪律



\### 5.1 逻辑与展示分离

组件内部如有复杂逻辑，应优先拆到纯函数或小型辅助模块中。



\### 5.2 不重复定义概念

以下概念在项目中必须统一定义：



\- 数学角度规范化

\- 向量方向

\- 坐标系原点与方向

\- 题目难度等级

\- 错题定义

\- 提示解锁规则



\### 5.3 不局部发明新范式

新增 feature 时不得自行创造独立风格的数据流或坐标体系。



\## 6. 测试纪律



\### 6.1 数学逻辑必须先测

凡是新增数学逻辑、边界处理、状态转换，都应优先补测试。



\### 6.2 回归测试优先

改动现有模块时，必须确认不会破坏：



\- 单位圆

\- 向量交互

\- 图像变换

\- 辅助角

\- 解三角形

\- 题库与错题系统



\### 6.3 测试关注点

测试应覆盖：



\- 纯函数正确性

\- 边界值

\- 逆向一致性

\- 状态更新逻辑

\- 交互数据流一致性



\## 7. 文档纪律



\### 7.1 变更必须可追踪

重要功能改动后，应同步更新：



\- `ROADMAP\_PROGRESS.md`

\- 必要时的架构说明

\- 测试说明



\### 7.2 代码注释只解释必要约束

注释应解释“为什么这样做”，而不是重复代码本身。



\## 8. 禁止项清单



以下行为默认禁止：



\- 在 feature 中复制数学逻辑

\- 在 Store 中保存派生量

\- 在 math 中引用 React 或 DOM

\- 以局部便利破坏全局结构

\- 用硬编码掩盖可复用抽象

\- 让 UI 层承担数学真值职责

\- 让数学层承担视图职责
