# MathVision 数学交互设计规则 (Math Rules)

本规则文件定义了 Agent 在实现 MathVision 核心数学内容、计算逻辑和交互演示时必须遵守的**硬性约束**。

## 1. 向量优先律 (Vector Priority Rule)
在涉及几何位置、方向、力学、投影、夹角及综合几何建模的页面与逻辑中，**必须优先使用向量语言与点积关系来建立和描述数学对象**，随后再将其映射到三角函数或代数解析式上。

### 1.1 绝对禁止
- 禁止脱离几何图形和向量语义，直接在页面上抛出孤立的推导公式或代数结论。
- 禁止在未定义相关基底向量的情况下，直接写出含混的几何解析式。

### 1.2 适用范围
- 解析几何与几何建模演示。
- 力学、运动类的模拟实验。
- 点积、投影、夹角、三点共线、垂直相关的理论推导页面。

### 1.3 例外范围
- 三角函数的基础定义（如弧度制）。
- 单位圆与纯三角诱导公式的演示。
- 重点在于说明“函数图像自身特性”（振幅、周期、相位）的页面。

## 2. 反向引导律 (Socratic Guidance Rule)
为了保证学习效果，系统交互应具备启发性。

### 2.1 规则要求
当系统判断用户处于入门、困惑状态，或首次接触某个知识点模块时，**优先提供“提问式”的轻量化引导组件**。

### 2.2 场景规范
- **首次进入知识点**：在页面核心区域先抛出一个启发式问题（例如：“拖动点A，观察角度与边长的关系，你发现了什么？”），用户进行初步交互后才显示结论。
- **错题复盘**：在给出正确答案前，提示用户“是否需要先查看相关概念的动画演示？”。
- **练习模式卡点**：当用户停滞不前时，提供渐进式提示，而不是直接甩出解析。

### 2.3 不适用范围
- 用户已明确目标的功能开发预览（直接进入核心功能）。
- 直接演示模式和公式速查页。

## 3. 计算与状态同步规则
在实现底层的代数与几何计算时，遵循以下纪律：
- **无状态计算优先**：复杂的几何位置关系和函数值应当从唯一的基础变量（如角度、基底坐标）派生，不能维护两份独立且可能冲突的状体。
- **防溢出与边界处理**：在涉及 `tan(x)` 等存在未定义点的函数时，必须明确处理 `π/2 + kπ` 的边界状态。拖拽交互时避免将控制点逼入导致计算崩溃的奇异点。
