# MathVision UI 与交互设计规则 (UI Rules)

本规则文件定义了 Agent 在设计和实现 MathVision 交互界面时必须遵守的**视觉与交互的硬性约束**。

## 1. 视觉感知优先律
不把产品做成自动化代数推导器，也不把页面做成纯公式展示页。
- **优先交互与图形**：优先通过动态几何图像和可拖拽实验解释公式本质。
- **辅助符号推导**：只有在完成视觉动画解释后，才在其旁边或下方补充必要的公式和推导过程。代数公式应当是被图像“证明”的结论，而非脱离图像存在的本体。

## 2. 视觉一致性原则 (Visual Consistency)
为保证学习过程认知的连续性，交互动画的界面布局必须高度一致。

### 2.1 三屏联动结构
在所有适合的场景下（如三角函数、诱导公式、图像变换、向量点积、解三角形等），尽量遵循“三屏联动”布局（PC 端）：
1. **左侧（操作区/根基区）**：呈现底层数学对象（如单位圆、基础三角形、基础向量），这是用户可拖拽、可交互的核心。
2. **中间（联动区/衍生区）**：呈现基于左侧操作产生的函数图像、点积曲线等。
3. **右侧/下侧（数值与公式区）**：实时跳动并更新当前状态的精确数值与推导公式。

*注意*：移动端响应式布局下，可降级为“上下联动”或“选项卡切换联动”，但要确保操作对象与反馈数据的就近原则。

### 2.2 杜绝孤岛现象
- **避免孤立呈现**：决不允许出现与当前交互无关的孤立函数图像，或没有任何交互和图形支撑的干瘪公式页。数学对象、向量关系与函数图像之间必须存在明确的映射、连续且统一的联动关系。

## 3. UI 交互体验规范
### 3.1 “即时响应”与平滑动画
- **拒绝顿挫**：所有拖拽操作（如拖动三角形顶点、拖动角度滑块、拖拽向量终点）必须提供 60FPS 级别的顺滑实时响应（依托 Zustand 等高性能状态库和 RequestAnimationFrame）。
- **参数变化可视化**：使用滑块控制参数时，图形形变必须连续，不能是离散的“跳跃”。

### 3.2 布局与配色克制
- **减少干扰**：UI 以极简风格为主，背景使用大面积留白或柔和底色。突出重点数学对象的色彩对比度（如关键点用鲜艳的红色，主要函数线用蓝色等）。
- **无障碍与辨识度**：考虑到教育产品的特性，公式排版必须使用标准数学字体（如 LaTeX/KaTeX 渲染），且字号要足够大，保证高辨识度。
